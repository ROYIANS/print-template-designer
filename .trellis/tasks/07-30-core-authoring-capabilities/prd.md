# 核心组件创作能力与画布内编辑

## 背景

PTD v2 已经具备专业画布、选择与变换、组件目录、属性面板、历史、剪贴板、多页面和
框架无关 Renderer，但部分目录项目前只有“可创建、可渲染”的外壳，没有完整的内容编辑路径：

- `RoyText` 只把 HTML 字符串写入 `innerHTML`，属性面板只能编辑 HTML 源码。
- `RoySimpleTable` 与 `RoyComplexTable` 能渲染既有结构，却没有专用表格编辑器。
- `RoyImage`、`RoyQRCode` 与 `RoyBarCode` 缺少可用的内容配置入口，默认插入后可能为空。
- `RoySimpleText` 只能在属性面板修改，尚未恢复 Legacy 已有的画布内直接编辑体验。

如果现在先完成 Web/Server 持久化，产品只会可靠保存功能不完整的模板。本阶段先建立核心组件
可用性基线，再进入应用命令、模板生命周期与完整前后端部署。

## 产品目标

让被目录标记为“可用”的基础组件满足统一创作链路：

```text
创建 → 合理默认内容 → 画布或专用面板编辑 → 即时渲染
    → Undo/Redo → 复制粘贴 → 序列化 → 重新载入一致
```

用户应能在不编写 HTML 或手工修改 JSON 的前提下，完成一张包含文本、富文本、图片、编码和
静态自由表格的真实单据版面。

## 设计上下文

- 目标用户：报表开发者与设计师。
- 使用场景：长时间、精密地制作打印模板和业务单据。
- 产品语气：精确、紧凑、冷静的数字印前工作台。
- 桌面端优先直接操纵；移动端保持内容可达，但不伪装成完整移动排版工作站。
- 内容工具应贴近当前对象或文字选区，避免为每次编辑打开遮断画布的大型模态框。

## 核心决策

### 1. 编辑器与 Renderer 分层

- `@ptd/components` 继续只负责框架无关、确定性的 DOM 渲染，不依赖 React 或富文本编辑器。
- `@ptd/react-designer` 负责画布内编辑器、选区工具、专用内容面板和编辑会话。
- `@ptd/core` 负责有类型的组件内容合同、规范化、序列化迁移及纯函数命令。
- Tiptap、Slate、Lexical 等编辑依赖只能进入 `@ptd/react-designer`，不得泄漏到 Renderer 包。

### 2. 画布内编辑优先

- 单击仍负责选择组件；双击或明确的“编辑内容”命令进入内容编辑态。
- 新绘制的普通文本框与富文本框在提交几何后直接进入编辑态。
- 编辑态下组件不响应移动、缩放、框选、删除和画布快捷键。
- 锁定组件不能进入编辑态。
- Escape 取消当前编辑会话；显式完成、失焦到画布或切换组件提交会话。
- 中文输入法组合期间，Enter/Escape/失焦不得造成错误提交或退出。

### 3. 历史边界

- 进入编辑态时开启一个组件内容 Gesture。
- 富文本编辑器内部的 Ctrl/Cmd+Z 只操作当前编辑会话的内部历史。
- 完成编辑时，整个会话最多形成一个 PTD 文档历史节点和一次最终 Host 变更。
- 取消编辑恢复进入时的精确内容，不写入 PTD 历史。
- 不能让每个输入字符各自成为外层 Undo 节点。

### 4. 目录必须诚实

- 具备创建、编辑、渲染和往返能力的组件才可标记为“可用”。
- 只有 Renderer、没有可用编辑路径的复杂组件必须降级为“规划中”或明确的只读预览。
- `RoyComplexTable` 在数据驱动、重复明细和自动分页合同确定前，不得暗示已经是完整报表表格引擎。

### 5. 组件采用工具式创建

- Sidebar 中所有可用组件点击后只切换创作工具，不立即居中插入组件。
- 用户在 Paper 上拖动定义 Frame；正反向拖动均需归一化并限制在页面边界内，QR 始终保持正方形。
- 直线、矩形、椭圆和星形保持连续绘制；文本、富文本、图片、编码和表格完成一次后回到 Select。
- 普通文本与富文本完成拖框后直接进入内容编辑；其他一次性工具保留新组件选中态供属性配置。
- 小于 4 CSS px 的拖动和所有取消路径不创建 Schema、不写历史，也不切换当前工具。

## 实现范围

### 工作包 A：共享内容编辑会话

- 增加实例级 `editingComponentId` / 编辑模式状态，不写入 `TemplateSchema`。
- 建立 Enter、Commit、Cancel、Blur、Selection change、Lock、Unmount 的完整状态机。
- 让 Component Adjuster 在编辑态隐藏或冻结移动/旋转/缩放控制。
- 为 Portal/Floating 工具提供 PTD 主题、层级、焦点和点击外部合同。
- 在 75%、100%、150% 缩放及旋转组件上验证鼠标、选区和工具位置。
- 为 IME composition、粘贴、Escape、窗口失焦和组件删除提供清理路径。

### 工作包 B：普通文本

- 画布内直接编辑，多行内容可用。
- 普通文本采用纯文本合同；Renderer 不再用未经处理的 `innerHTML`。
- 支持字体、字号、字重、斜体、下划线、删除线、行高、字距、颜色和对齐。
- 复制粘贴默认清除外来富文本样式，只保留文字和换行。
- 属性面板保留内容与排版入口，但不再是唯一编辑方式。

### 工作包 C：富文本

- 在组件框内原位 WYSIWYG 编辑，不复刻 Legacy 的大型模态编辑器。
- 第一版支持段落、换行、标题、粗体、斜体、下划线、删除线、字体、字号、文字颜色、
  背景高亮、行高、左/中/右/两端对齐、有序/无序列表、链接和清除格式。
- 文字选区出现紧凑的上下文工具；无选区时可通过对象 Quick Bar 进入编辑或打开完整排版控制。
- 持久化合同暂定为经过规范化和白名单清洗的语义 HTML。
- `@ptd/components/RoyText` 只渲染清洗后的 HTML，不携带编辑器运行时。
- 粘贴内容必须移除脚本、事件属性、危险 URL、不可支持标签和无界内联样式。
- 固定版面中内容默认受 Frame 尺寸裁切；自动增高和跨页流动不属于本阶段。

富文本实现的初步推荐是 Tiptap 3，但必须先完成一个隔离 Spike，验证 React 18、中文 IME、
画布缩放/旋转、Bubble Menu 定位、HTML 往返和双层 Undo 后，才能加入正式依赖和 lockfile。

### 工作包 D：图片、二维码与条形码

#### 图片

- 图片 URL/Data URL、预览、替换、加载失败状态。
- Alt Text、`contain` / `cover`、对象位置、保持比例、背景、边框、圆角和透明度。
- 本阶段不实现服务端资源库；临时 `blob:` URL 不得写入持久化 Schema。
- 如从字符串升级为结构化内容，必须提供旧模板迁移。

#### 二维码

- 内容、前景/背景色、纠错等级、边距和错误反馈。
- 使用可工作的非空默认内容，插入后立即可见。

#### 条形码

- 内容、码制、前景色、是否显示人类可读文本及非法输入反馈。
- 使用 Code 128 等宽容默认码制和有效示例值。
- Renderer 不再静默吞掉所有错误；编辑器应显示可操作的校验信息。

### 工作包 E：自由表格

- 新增时生成真实 2×2 默认表格，而不是空白 Renderer。
- 单元格选择、范围选择、双击内容编辑和键盘导航。
- 添加/删除行列、调整行高列宽、合并/拆分单元格。
- 单元格文字、对齐、内边距、背景、边框和基础字体样式。
- 表格结构命令使用纯函数更新 Schema，不依赖 DOM 几何或深度 Watch。
- 每个结构命令是一次原子 Host 变更和历史节点。
- 第一版单元格采用纯文本，不嵌套完整富文本编辑器。

### 工作包 F：结构表格与目录校正

- 审核 `RoyComplexTable` 的真实能力。
- 如果本阶段没有实现 header/body/footer 专用编辑器，将它降级为“规划中”，保留旧模板只读渲染。
- 重复明细、字段绑定、汇总、跨页表头、行拆分和自动分页留给数据源/派生分页阶段。
- 图形组件和 Group 只做回归验证，不重复重写已完成能力。

## Schema 与安全要求

- 为富文本、图片、二维码、条形码和表格建立公开的内容类型与运行时守卫。
- 不允许在 Renderer 中以 unchecked cast 假定任意 `propValue` 形状。
- Schema 发生持久化结构变化时提升 `_version`，实现确定性向前迁移并增加旧样本测试。
- 普通文本永远按文本渲染；富文本只允许注册节点/标记和安全 URL 协议。
- 任何本地文件或临时对象 URL 都必须在持久化前转换为稳定来源或拒绝保存。

## 非目标

- Web/Server 模板列表、保存、版本历史和冲突处理。
- 服务端资源上传、对象存储和资产管理。
- 数据字段/表达式、REST/Excel 数据源与实时业务数据预览。
- 重复明细、结构表格数据流、自动溢出分页。
- 打印预览、PDF/Word 导出。
- 协同编辑、评论、AI 写作能力。
- 完整移动端富文本排版工作站。

## 验收标准

- 普通文本和富文本均可在画布中直接进入、完成和取消编辑。
- 所有可用目录项均通过“选择工具 → Paper 拖框”创建；Sidebar 点击本身不改变 Schema。
- Shape 完成后保持连续绘制；其他组件完成后回到 Select；新文本自动进入编辑。
- 中文 IME 输入不会因 Enter、Escape、工具条点击或失焦丢字或意外退出。
- 富文本所有第一版格式能够编辑、复制、序列化、反序列化并保持视觉一致。
- 富文本粘贴与载入不能执行脚本、事件属性或危险链接。
- 一次文本编辑会话最多形成一个 PTD 历史节点；取消不形成节点。
- 图片、二维码和条形码新增后可见，所有核心内容无需修改 JSON 即可配置。
- 自由表格可创建、编辑单元格、增删行列、合并拆分并正确 Undo/Redo。
- `RoyComplexTable` 要么具备诚实的专用编辑能力，要么明确降级为规划/只读状态。
- 所有“可用”目录项通过创建、编辑、复制、锁定、序列化和重新载入的能力矩阵。
- 两个 Designer 实例不共享编辑态、选区、富文本实例或历史。
- React Designer TypeScript、ESLint、Vitest、package build、Web build、Prettier 和
  `git diff --check` 全部通过。
- 浏览器验收覆盖 1600×1000、1366×768、1024×768，以及 75%/100%/150% 画布缩放。

## 阶段门

1. 用户确认富文本依赖选型与持久化合同。
2. 富文本 Spike 通过 IME、缩放、选区工具和双层历史验证。
3. 再添加依赖并更新 lockfile。
4. 按共享编辑会话 → 文本 → 媒体/编码 → 自由表格 → 能力矩阵顺序实现。
5. 本任务完成后，下一阶段进入“设计器应用命令与文档状态合同”，随后接通 Web/Server。
