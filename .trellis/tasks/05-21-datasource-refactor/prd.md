# 数据合同、组件绑定与实时校样

## 状态

本任务的实现、自动化验证与真实浏览器验收已经完成，仍保持 Trellis `in_progress`，等待主会话提交并归档。
Foliq 现在可以声明数据结构、把字段绑定到组件，并在不修改模板和编辑历史的前提下使用真实样例或
Host 临时数据校样。

本任务不再沿用旧占位标题中“Excel/REST 直连一次完成”的范围。Excel/CSV 文件连接器、REST Server
代理、自动分页、打印和文档导出都依赖本任务建立的稳定合同，应拆成后续独立任务。

## 实现前背景

Foliq 已经完成专业 React Designer、组件创作、页面与属性配置、GitHub 登录、PostgreSQL 模板持久化、
文件工作台、模板版本历史、恢复和 409 冲突保护。当前应用已经能够安全地设计、保存、重新打开和管理
静态模板，但数据能力仍是早期兼容骨架：

- `TemplateSchema` 只保存扁平 `dataSource` 与无约束 `dataSet`；
- `DataFieldType` 把字符串、数组等值类型与金额、中文大写、当前日期等显示转换混在一起；
- `DataBindingEngine` 只识别 `[::field::]` 字符串占位符；
- 普通 Designer Renderer 不向组件传递数据上下文，只有 `RoySimpleText.resolveWithData()` 保留孤立入口；
- 数据面板只能只读显示字段，并明确标注拖拽绑定与表达式校样尚未实现；
- 文本、富文本、图片、二维码、条形码和表格没有共享的绑定目标与诊断合同；
- 示例数据、Host 运行时数据和未来外部连接凭据尚未分层。

如果在这些边界未稳定时直接实现 REST、PDF 或自动分页，会把临时数据结构扩散到 Core、Designer、
Web、Server 和 Export，随后需要进行破坏性重构。

## 目标

### 1. 建立可演进的数据模型

Core 必须建立一个框架无关、可运行时验证、可序列化并兼容旧模板的数据合同：

- 基础值类型与显示格式化分离；
- 字段具有稳定 ID、用户可读名称、数据路径、值类型与必要的数组/对象结构；
- 支持嵌套对象和数组字段，不把所有字段压成不可管理的扁平字符串；
- 模板字段定义、受限示例数据、Host 运行时数据与未来连接配置职责明确；
- 连接 Secret、Token、Cookie、认证头和原始凭据绝不能进入 `TemplateSchema` 或模板版本；
- 当前 v1 `dataSource`、`dataSet` 和 `[::field::]` 模板可以读取并经过单一 Core 入口归一化；
- canonical 写入只有一个事实来源，不能长期同时维护两套可编辑数据模型。

基础值类型至少覆盖：字符串、数字、布尔、日期、对象、数组与未知值。金额、小数位、中文大写数字、
中文大写金额和日期格式属于显示格式化规则，不再伪装成底层值类型。

### 2. 建立结构化组件绑定

组件绑定必须表达“哪个组件属性消费哪个数据表达式”，不能继续只依赖扫描任意字符串：

- 简单文本支持静态文字与字段插值混合；
- 富文本只允许安全文本槽位插值，不把运行时数据作为任意 HTML 执行；
- 二维码和条形码可绑定内容；
- 图片可绑定安全来源地址，同时保留静态 alt、fit 和 position；
- 自由表格的静态单元格文本可插值；
- 组件可绑定属性由共享合同声明，Designer 和 Renderer 不得各自维护另一份散落映射；
- 旧 `[::field::]` 只作为兼容输入，经 Core 解析后进入同一求值与诊断路径；
- 本任务不开放 `eval`、`Function`、任意 JavaScript、网络表达式或用户脚本。

绑定应引用稳定字段身份；字段的数据路径可以演进，而不要求在所有组件内容中做不可控字符串替换。

### 3. 建立确定性的渲染上下文

预览、打印和未来服务端导出必须能够用相同输入得到相同结果。Core 需要定义明确的 Render Context，
至少包含运行时数据、当前记录、locale、timeZone、显式 `now` 和渲染模式。

- 日期与时间转换不得在每个组件内部直接读取系统时钟；
- Designer、只读 TemplatePreview 和未来 Export 应复用同一求值入口；
- 缺失字段、类型不匹配、格式化失败与不安全资源需要形成结构化诊断；
- Renderer 必须区分 ready、missing、invalid，以及媒体组件既有的 loading/error 状态；
- 数据求值不得修改输入模板。

### 4. 提供非破坏性的实时校样

Designer 数据面板升级为可持续操作的专业工作表面：

- 支持拖入/选择 JSON 文件，以及在专用表面粘贴 JSON；
- JSON 解析成功后先展示根结构、记录数、字段推断与问题，再由用户明确应用；
- 以可搜索字段树展示对象、数组、字段名称、路径和值类型；
- 当前选择组件时，字段可以通过明确按钮或绑定选择器连接到兼容属性；
- 拖拽可以作为效率增强，但点击与键盘必须具备同等可达路径；
- 支持选择示例记录，并切换“设计内容 / 数据校样”；
- 一般管理与校样使用数据面板、Popover、Inline 或 Side Sheet，不使用大型阻断 Modal；
- 错误在触发表面或对应组件附近显示，不能只用 Toast 或静默空白。

数据面板不能退化为传统后台 CRUD 表格，也不能堆放未经封装的原始表单控件。它应复用 Foliq Inspector
Control、Panel、Segmented、Popover、Sheet、Field Tree 和诊断视觉合同，保持暖灰、纸白和档案墨蓝体系。

### 5. 保持 Designer 与 Web 生命周期正确

- 编辑字段模型、示例数据、绑定和格式化规则属于模板更改，进入一次合理的 History/Dirty 边界；
- 切换记录、开关校样、展开字段树和搜索字段属于实例 UI 状态，不触发 `onChange`、Dirty 或 Undo；
- 校样产生的解析结果和未来派生页面不写回 `TemplateSchema.pages`；
- 保存、刷新重开、复制、另存为、版本预览和历史恢复必须保留字段与绑定；
- 外部 `value` 替换后，校样 UI 必须清除或校正失效记录、选择和诊断，不能泄漏上一模板状态；
- `TemplatePreview` 默认保持模板定义的稳定缩略图行为；只有 Host 明确提供 Render Context 时才渲染
  对应数据，不允许文件工作台缩略图随机显示一次运行时记录；
- Web 可以注入运行时校样数据，但本任务不新增 Server 数据连接器 API。

## 数据流边界

```text
JSON 文件 / 粘贴 JSON / Host 运行时数据
                    │
                    ▼
        Core 入口验证与字段推断
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
模板字段与受限示例数据     临时运行时数据
          │                   │
          └─────────┬─────────┘
                    ▼
        Binding + Render Context
                    │
                    ▼
         只读派生的校样渲染结果

未来 Server Connection ──只输出运行时数据；Secret 不进入以上模板链路
```

Core 负责数据合同、验证、推断、路径解析、格式化、求值与诊断；Components 负责使用已解析内容稳定渲染；
React Designer 负责字段、绑定和校样交互；Web 负责应用级运行时数据来源与模板生命周期。任何一层都不能
越级访问未来连接凭据或复制另一层的求值规则。

## 首批支持矩阵

| 组件     | 支持范围                             | 本轮不做                     |
| -------- | ------------------------------------ | ---------------------------- |
| 简单文本 | 纯字段与混合文本插值、格式化         | 任意脚本表达式               |
| 富文本   | 受控文本插值并保持 HTML 安全         | 运行时 HTML 注入、条件节点   |
| 二维码   | 内容字段绑定，复用既有校验           | 动态样式和批量二维码         |
| 条形码   | 内容字段绑定，复用码制校验           | 根据字段动态切换码制         |
| 图片     | 来源字段绑定，复用安全协议与加载状态 | 上传服务、带认证远程抓取     |
| 自由表格 | 静态单元格文本插值                   | 数组扩行、重复表头、自动分页 |
| 结构表格 | 只保持旧模板可读                     | 创作、分区绑定与数据流       |

## 示例数据约束

- 首版接受 JSON object 或 object array；primitive 根值必须给出可操作错误；
- object 根值视为一条记录，object array 视为多条记录；
- 空数组、混合类型数组、递归深度、字段数量和序列化体积必须有明确上限与诊断；
- 推断只描述观察到的结构，不把缺失值自动伪造成可靠类型；
- 模板保存的示例数据应有体积上限，并明确提示它会进入模板版本；
- 用户可以移除示例数据而保留字段和绑定；
- Host 临时注入数据默认不写入模板，除非用户明确选择“保存为示例”。

具体上限在实现研究中依据浏览器交互、Server 请求体边界和模板版本成本确定，并由一个共享常量合同
约束解析、UI 提示与运行时验证，不能散落魔法数字。

## 明确不在本任务范围

- Excel/XLS/XLSX/CSV 解析；
- REST、GraphQL、SQL、Webhook 或 Server 数据代理；
- Secret 加密、连接测试、计划刷新和连接审计；
- 数据源跨模板共享或团队连接库；
- 数据驱动重复明细、结构表格创作、数组扩行和自动分页；
- 打印预览、浏览器打印、PDF、Word 和批量打印；
- 任意表达式语言、JavaScript、公式编辑器、条件显示和用户脚本；
- 本地崩溃草稿、自动保存、软删除、收藏和团队项目空间。

## 交互与可访问性要求

- JSON 导入、字段绑定、移除示例和字段模型变更必须有明确结果，不使用伪成功按钮；
- 高风险替换现有字段模型且会使绑定失效时必须先展示影响摘要，再由用户确认；普通添加和绑定不弹 Modal；
- 数据字段行、记录选择器和绑定目标可通过键盘操作，并具有可理解的名称、选中态和错误关联；
- Pointer 拖拽不是唯一入口；Touch/Pen 下仍可完成完整流程；
- Popover、Sheet 和 Picker 必须限制在 Designer 视口内，Escape 只关闭最上层表面并恢复焦点；
- 校样模式有文字状态，不仅依赖颜色；字段缺失和无效绑定有就地说明；
- 窄屏允许数据面板占据可用工作区，但不能产生页面级水平溢出。

## 兼容与迁移要求

- 所有现有空 `dataSource: []`、`dataSet: {}` 模板继续有效；
- 旧 `DataSourceField` 与 `[::field::]` 必须经过测试覆盖；
- 迁移只在明确的规范化/编辑/保存边界发生，不因单纯预览偷偷改变模板；
- 未知字段类型、未知格式化器或失效字段引用必须保留可诊断信息，不能无声删除；
- Server 的深层 TemplateSchema 运行时验证与 Web API Client 验证必须同步接受 canonical 合同；
- 如果提升 `_version`，必须提供从当前版本到新版本的明确归一化路径和回归测试。

## Definition of Done

1. ✅ 用户可以拖入、选择或粘贴 JSON object/object array，并在确认前查看记录数、字段数、体积、
   深度、诊断和绑定影响摘要；只有明确应用才写入模板。
2. ✅ Designer 提供可搜索、可展开、可通过按钮与键盘操作的嵌套字段树，区分对象、数组与基础类型。
3. ✅ 简单文本、富文本、二维码、条形码、图片和自由表格活动单元格均通过 Core Registry 的共享目标
   合同建立结构化绑定；多选、锁定、无选择和不支持状态均有明确说明。
4. ✅ 简单文本支持 literal 与多个 field segment 的结构化组合，字段默认 formatter 与值类型分离。
5. ✅ 样例记录和 Host 运行时记录可以即时切换校样；记录切换与设计/校样切换不产生 Dirty、History
   或 `onChange`。
6. ✅ 字段名称、默认 formatter、示例数据和绑定变更具有一次性、可撤销的历史边界；结构等价的重复
   应用或绑定是 no-op。
7. ✅ 缺失字段、类型/格式化失败、不安全图片来源和编码内容错误沿统一诊断与组件既有错误状态呈现，
   不会静默形成空白。
8. ✅ canonical 数据与绑定已经通过现有模板 CRUD、刷新重开、复制、另存为、版本预览和历史恢复链路
   round-trip 验证。
9. ✅ 旧 `dataSource/dataSet/[::field::]` 可以通过单一 Core normalizer 兼容读取；只读预览和校样不会
   偷偷迁移，显式编辑/保存才进入 canonical 写入边界。
10. ✅ Host 通过公共、类型安全的 Render Context 注入临时数据、locale、timeZone 和显式 `now`；运行时
    数据默认不进入模板或版本。
11. ✅ `TemplatePreview` 默认保持静态、确定性的模板缩略图；只有显式 Render Context 才解析绑定，版本
    历史预览不会继承当前 Editor 的临时校样数据。
12. ✅ 已使用真实冷链出库标签数据完成 `1280×720` 与 `390×844` 浏览器验收；JSON 导入、字段绑定、
    多记录校样、保存重开和错误诊断均通过。验收中发现的 compact Scrim stacking context 缺陷已经修复，
    资源面板内部控件可达，Scrim 仍能关闭 Canvas overlay。
13. ✅ Core、Components、React Designer、Web 与 Server 的相关测试、typecheck、顺序 build、Frontend
    ESLint、Prettier、Trellis context validation 与 `git diff --check` 已通过。
14. ✅ README、Core/Components/React Designer 文档及相关 Trellis spec 已与最终合同和能力边界同步。

## 最终验收边界

- 已完成真实 `1280×720` 与 `390×844` 冷链业务数据的端到端浏览器验收；compact 资源面板位于 Scrim
  之上，内部 JSON 导入等操作不会再误命中 Scrim。
- 已完成现有 Web/API/Server Schema 的自动化 round-trip、大小限制和错误响应验证。
- Docker Nginx → 编译后 Server 的真实大请求 `413 Payload Too Large` 端到端验证尚未执行；当前只确认
  Nginx、Server 与共享数据限制的配置/自动化合同，不能把这一项记为真实部署验证通过。
- Excel/XLS/XLSX/CSV、REST/SQL/GraphQL 连接器、Secret 管理、打印预览、PDF/Word、重复明细、自动分页
  和批量打印仍属于后续任务，本任务没有以占位按钮或临时 API 冒充这些能力。

## 已确认决策

1. 本任务是 Web 模板生命周期之后的下一条产品主线。
2. 复用原 `05-21-datasource-refactor` 占位任务，但收敛标题和范围。
3. 第一版以 JSON 示例数据和 Host 注入数据打通闭环，不实现 Excel 或 REST。
4. 类型、格式化、绑定、运行时数据与连接凭据必须分层。
5. 校样是非破坏性的派生视图，不进入 TemplateSchema 手工页面、Dirty 或 Undo/Redo。
6. 不通过扩大 Modal 使用来完成数据管理；优先 Panel、Sheet、Popover 和 Inline 状态。
7. Export 任务继续保持规划状态，直到本任务的 Render Context 和绑定合同稳定。
