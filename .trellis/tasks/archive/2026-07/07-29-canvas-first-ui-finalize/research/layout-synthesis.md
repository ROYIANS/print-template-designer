# Canvas-first 布局研究与现状综合

## 输入

- 用户提供的“通用设计器”竞品截图：顶部组件 Ribbon、第二命令栏、左右工具窗和中央纸张。
- 当前 PTD PR4-A 工作台：48px App Bar、44px 双 Deck Command Bar、48+252px 左侧栏、
  288px Inspector、26px Status Bar。
- PTD 目标：给同时承担报表开发与版式设计的个人制作者使用，具有 InDesign 精神但不复制 Adobe。
- 现有 `ptd-ui-system.md`、Zed/Workshop 视觉研究和已实现的真实标尺/参考线合同。

## 竞品为什么显得空间利用率高

1. 几乎所有顶部空间都承载可执行工具，没有独立的大品牌区或卡片容器。
2. 创建工具、编辑命令、标尺形成连续纵向层级，纸张紧接工作区。
3. 左侧默认展示数据字段，右侧默认展示属性，符合报表任务的两个核心输入。
4. 面板内容采用高密度平面行而非大 tile，单屏可见字段更多。
5. 页面概览使用独立小窗，不长期占据整列。

截图宽度约 2048px，左右面板合计仍接近 700px；中央区域显得宽并不代表它的固定 Chrome
比例显著优于 PTD。可吸收的是任务密度和画布优先，不是大面积青色 Ribbon 或浮动窗体外观。

## 竞品不应复制的部分

- 第一行所有创建工具近似同一视觉权重，扩展后必然拥挤。
- 第二行图标密度过高、含义依赖长期记忆，禁用态形成大片噪声。
- 右侧表单过长、缺乏按工作流分组和渐进披露。
- 多处窗口标题、关闭按钮、滚动条和青色条带形成旧桌面软件感。
- 数据、图层、页面和资产没有稳定的资源信息架构。
- 高密度来自压缩，而不是上下文相关性。

## 当前 PTD 外壳的结构问题

### 永久 Chrome 过多

- 92px 顶部高度同时承载品牌、全部编辑命令和视图命令。
- 左侧五入口 Rail 是后台导航模型，组件目录在排版阶段仍长期占宽。
- Inspector 无选择时仅显示空态，固定 288px 没有产生任务价值。

### 命令缺乏上下文

- 历史、剪贴板、层级、对齐、组合、页面、标尺、参考线和缩放同层陈列。
- 大量禁用按钮保持可见，用户必须扫描整条 Command Bar。
- 页面设置同时散落在 App Bar 摘要、Toolbar 方向按钮和左侧全局面板。

### 响应式是隐藏而非适配

- 1180px 以下直接隐藏左内容面板。
- 920px 以下直接隐藏 Inspector，缺乏恢复入口和 overlay 行为。
- 固定区域变化时，现有 Chrome 没有围绕主画布重排。

## 目标模型

### 同一用户的两种工作上下文

“报表开发者”和“设计师”不是两套模式：同一任务会在放置组件、绑定字段、调整几何、预览长文本、
修改规则和重新排版之间循环。显式模式切换会制造中断；应由活动资源、当前选择和 Inspector 分区
自然形成工作上下文。

### Canvas-first shell

- Document Bar 只回答“正在编辑什么、是否保存、如何载入/保存/预览”。
- Context Bar 只显示当前页面、组件、多选或参考线真正相关的命令。
- Tool Dock 提供高频创建与选择工具。
- Resource Panel 稳定承载 Pages/Layers/Data/Assets，可折叠和调整。
- Inspector 为页面或对象提供完整属性，不出现浪费整列的空态。
- Status Bar 承担测量、当前页、参考线状态和缩放。

## PTD 的后续差异化：数据校样台

未来数据阶段可以在 Status Bar 之上增加按需展开的 Data Proofing Dock，用于样例记录、表达式
求值、溢出、缺失字段、分页和打印预检。它是 PTD 区分普通画布编辑器与传统报表设计器的关键，
但当前没有真实数据引擎，因此本 UI 任务只保留布局和术语决策，不渲染假错误数或空工具台。

## 实施约束

- 复用现有 Canvas、Store、Catalog、Inspector 表单、Panel 原语和 Radix/Remix 依赖。
- UI layout state 必须实例隔离、模板外存储、模板历史外存储。
- 面板动态宽度使用 CSS 变量；静态视觉保持 CSS Modules/token。
- 组件创建继续走统一 Catalog/Factory。
- 不允许布局重构改变受控 Designer 合同或打印内容。
- 宽度策略以 Designer 容器为准，避免嵌入场景错误依赖整个浏览器 viewport。

## 决策

采用 Canvas-first Studio，而非继续润色 Workshop 双 Deck，也不采用竞品 Ribbon。UI 收官任务只
交付真实工作台骨架和现有能力迁移；数据校样、吸附、多页结构命令与表达式调试留给功能阶段。
