# 模板 JSON 导入导出

## 背景

Foliq 即将进入打印预览与 PDF 导出主线。在实现自动分页、表格智能分页、页眉页脚等专业排版能力前，需要先提供完整模板 Schema 的本地 JSON 交换能力，方便快速复制、手工调整和恢复布局。

本功能中的“模板 JSON”与数据面板已有的“数据 JSON”是两种不同能力：前者交换完整 `TemplateSchema`，后者仅用于字段建模、绑定与校样数据。

## 用户目标

- 从设计器导出当前正在编辑的完整模板，即使修改尚未保存到服务端。
- 从本地 JSON 文件导入一个模板，并把它作为未保存的新文档继续编辑。
- 导入过程不覆盖当前服务端模板，也不携带服务端身份或鉴权信息。
- 在错误文件、旧版本文件和未保存修改场景下得到安全、清晰的反馈。

## 范围

### 导出模板 JSON

- App Bar 提供明确的“导出模板 JSON”入口，不与数据 JSON 入口混淆。
- 导出当前内存中的最新 `TemplateSchema`，包含未保存修改。
- 通过 Core 的 canonical 序列化路径输出稳定、可读的 JSON。
- 导出内容包括 Schema version、pageConfig、pages、components、数据定义、示例数据与 bindings。
- 导出内容不包括服务端 template ID、owner、服务端 version、session、OAuth、secret 或数据库元数据。
- 文件名使用经过净化的模板标题，后缀为 `.foliq.json`；无可用标题时使用稳定的默认名。

### 导入模板 JSON

- App Bar 提供明确的“导入模板 JSON”入口，通过系统文件选择器选择本地 `.json` 文件。
- 文件必须经过 Core 的反序列化、兼容迁移、规范化和深层验证，禁止直接将 `JSON.parse` 的任意对象注入设计器。
- 成功后作为新的未保存文档打开：无服务端 ID、无服务端 version，不覆盖原模板。
- 导入文档沿用现有保存/另存为流程进入持久化。
- 替换当前文档前复用现有未保存修改保护；用户取消时不读取或替换文档。
- 同一文件可以连续选择并再次导入。
- 对 JSON 语法错误、不合法 Schema、不支持版本、文件过大、缺少页面及组件/数据合同错误显示可理解的中文错误。

### 交互与可访问性

- 不新增仅用于选文件的 Modal；使用隐藏文件输入并由菜单项触发。
- 反馈沿用现有应用级状态/提示模式，保持 Foliq 克制、精密的制版工具视觉。
- 文件输入与菜单入口支持键盘和屏幕阅读器。
- 移动端保留关键能力，不因窄屏隐藏导入导出。

## 非目标

- 不实现打印预览、浏览器打印或 PDF 导出。
- 不实现拖放导入、云端导入、模板市场或分享链接。
- 不改变数据面板中的数据 JSON 导入能力。
- 不导入或导出服务端记录元数据。
- 不修改 Foliq Logo、内部 `PTD` 技术标识或包名。

## 验收标准

1. 当前未保存编辑可完整导出并经 Core round-trip 后保持语义等价。
2. 合法 canonical 模板可导入，并以未保存新文档状态出现。
3. 兼容范围内的旧 Schema 可经迁移/规范化导入。
4. 导入不会更新、覆盖或复用原服务端模板 ID/version。
5. 当前有未保存修改时，取消替换会完整保留当前文档。
6. 无效 JSON、无效 Schema、过大文件和不支持版本均不会污染当前状态，并显示明确错误。
7. 导出文件名安全、稳定，且后缀明确表示 Foliq 模板。
8. App Bar 文案明确为“模板 JSON”，与数据 JSON 入口不混淆。
9. Core、React Designer 与 Web 的相关 typecheck、tests、lint/build 通过。
