# 画布工具栏排布调研

## 参考模式

### Figma：底部创作工具浮岛

用户截图中的工具栏把选择、抓手、基础创作工具和模式入口集中在底部中央，以分隔线切成稳定分组。
其价值不是深色皮肤，而是让“操作画布”与“打开面板”成为两套空间模型：前者靠近视线和鼠标落点，
后者留在页面边缘。

### Excalidraw：单一底部创作带

轻量画布产品通常把选择与图形创建放在一个连续工具带中，复杂或低频能力进入更多菜单。优点是学习
成本低，缺点是当产品存在页面、图层、数据和丰富上下文操作时，单层工具带容易过宽。

### Canva / 专业制版工具：常驻主工具 + 上下文层

内容创作工具常把常驻创建入口与“当前选中对象的操作”分开。主工具稳定不跳动，上下文层随页面、
选区或绘制模式变化；这样既保留功能密度，也避免用户在每次选中对象时重新寻找主工具。

## 当前 Foliq 事实

- `Sidebar.tsx` 当前同时拥有两类职责：
  - 选择、抓手、文本、形状、图片、简单表格、更多组件；
  - 素材、页面、图层、数据四个资源面板入口。
- `Toolbar.tsx` 当前同时拥有三类职责：
  - 撤销/重做；
  - 页面、单选、多选、辅助线和主动绘制工具的上下文命令；
  - 左资源面板与右属性面板的开关。
- `Designer.tsx` 使用 `AppBar + Toolbar + Workspace + StatusBar` 四行 Grid；删除 Toolbar 后可以直接
  回收一整行纵向空间。
- 选择、抓手、组件绘制、撤销/重做都直接调用同一个 `EditorStore`，因此重排入口不需要复制业务状态。
- `ComponentToolPicker` 当前锚定左 Rail，底部化时需要改为锚定新的“更多组件”按钮，并向上展开。
- Compact workspace 会把左右面板变成 overlay；底部浮栏必须保留 safe area，并在窄宽度下把低频工具
  收入更多菜单，而不是产生横向页面滚动。

## 可行方案

### A. 主浮岛 + 上下文薄层（推荐）

- 主浮岛常驻：撤销/重做、选择/抓手、文本、形状、图片、表格、更多组件、属性面板。
- 上方薄层复用现有 Toolbar 的页面/选区/辅助线/工具提示上下文。
- 左 Rail 只保留素材、页面、图层、数据。
- 优点：不丢现有命令；主工具位置稳定；符合用户提出的“两层”可能性。
- 代价：底部需要约 88–104px safe area；需要清晰区分两层的视觉权重。

### B. 单层全量浮岛

- 把历史、创作工具和上下文操作全部放入一条浮栏。
- 优点：形态最接近截图；实现表面简单。
- 代价：选中组件后工具数量和宽度大幅变化，主工具会跳位；标准/紧凑视口很难稳定。

### C. 单层主浮岛 + 上下文全部迁入右 Inspector

- 底部只保留创作工具和历史；页面/选区操作全部进入属性面板或 AppBar 菜单。
- 优点：画布最干净。
- 代价：明显扩大任务范围，需要重新设计页面属性、辅助线、图层和快捷操作的信息架构，不能算本次
  “重排入口”的低风险 MVP。

## 推荐结论

采用方案 A，但保持 Foliq 自己的“精密校样工具”视觉：暖纸灰浮岛、细边线、紧凑圆角、克制阴影、
档案墨蓝选中态和 Remix Icon。主浮岛稳定，上下文薄层按当前状态改变内容；两者共享同一定位容器，
不复制 EditorStore 或 Host command。

MVP 在 wide/standard 模式显示全部常用工具；compact 模式保留历史、选择/抓手、文本、形状、更多组件
和属性面板入口，图片/表格仍可从更多组件访问。画布滚动区域增加与浮栏高度对应的底部安全空间。
